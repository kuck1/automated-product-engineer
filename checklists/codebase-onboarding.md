# Codebase onboarding checklist

- [ ] Repository, branch or PR, runtimes, owners, and authority are pinned.
- [ ] Repository instructions and documentation inventory are complete.
- [ ] Representative read, write, failure, concurrency, and responsive/native journeys are traced.
- [ ] Current practices cite code, runtime, test, or documentation evidence.
- [ ] Documentation and implementation inconsistencies are explicit.
- [ ] Product requirements and material unknowns are separated from implementation choices.
- [ ] State, API, database, auth, design-system, testing, delivery, and documentation domains are reviewed where applicable.
- [ ] Strong existing contracts are marked for preservation.
- [ ] The team selected an ordered set of product-sized upgrade slices.
- [ ] Every slice has migration, rollback, proof, and completion criteria.
- [ ] Characterization or UI contract coverage precedes structural change where useful.
- [ ] E2E coverage follows a stable product and cross-boundary contract.
- [ ] The project-specific skill overlay reflects accepted local decisions.
- [ ] Each completed slice updates decisions, current practices, inconsistencies, and retrospective evidence.
- [ ] The final handoff is committed, shared in a draft PR when authorized, and leaves merge and release to the human owner.
