# Retrospective and Fix-Back Prompt

Review the completed delivery of **[FEATURE]** and improve the system that produced it.

Identify:

- product decisions discovered late;
- architecture or state boundaries that caused rework;
- design-system gaps;
- missing fixtures, states, or acceptance criteria;
- tests that caught real defects versus tests that created noise;
- CI, review, or deployment friction;
- reusable lessons for skills, templates, prompts, and reference code.

Turn each durable lesson into a concrete fix in the appropriate source of truth. Keep feature-specific history in the retrospective and move reusable guidance into the shared workflow. End with owners, follow-up scope, and evidence that the fix-back was applied.
